# Perceive 确定版方案与完整调研

调研日期：2026 年 10 月 6 日。依据：两个仓库的实际源码、产品官方说明、开源项目官方仓库与论文。

> 本报告的产品定义、五类输出和 Demo 长板已根据后续对齐修订。最新方案见 [Perceive 对齐修订方案](./Perceive对齐修订方案.md)。本报告的源码调查与模型资料保留作参考；实现与验收以修订方案的判断对象、类别和边界为准。

这是一份产品与科研原型方案，不是已经实现的功能清单。文中的延迟、识别效果和验收数字都是建议目标，尚未在你们系统上测得。

按你的最新要求：以科研研究为用途，不把非商业许可、现有设备显存作为筛选门槛；可以使用 API 或更大设备。选型主要看能力、证据是否可靠、实时输出能否实现。

## 1. 最终决定：做什么

**产品大类：实时多模态社会感知引擎。第一版产品定义：实时多模态交流状态感知引擎。**

它持续观察眼前的人，把“他说了什么、怎么说、脸和身体发生了什么”合在一起，输出当前交流状态、刚刚发生的变化，以及可以回看的依据。

**第一版的突出长板：及时抓住犹豫、澄清和表达受阻的出现与变化。**

例如：一个人开始说“这个方案我觉得可以……不过……我不太确定第二点”。系统在他还没说完整段话时，就发现表达从顺畅变成犹豫；随后定位到“第二点”的不确定表达，并指出这一判断来自哪句话、哪些停顿以及哪些可见动作。

这个长板属于“能力上的垂直切入”，不绑定餐厅、养老、销售或某个行业。第一版只分析一个被观察的人，先把这件事做扎实。

完整性保留在输入和输出链路上：声音、画面、文字、轻量身体观察、时间变化、质量控制、证据和接口都要有。深度集中在交流状态与变化上，其他部分提供支持，不要求每项都形成独立的顶级算法。

### 为什么选择这个长板

1. 语意是核心，声音和画面真正有机会补充文字没有的信息。
2. 判断能落到具体片段，容易验证，不只是给出一个“开心 70%”的数字。
3. 不依赖个人长期画像，符合你对 Perceive 的边界。
4. 后面的 Understand、Predict、Engage 都能使用这些结果。
5. 两个现有项目已经有采集、声音处理、面部分析、状态缓存和模型接口，能复用工程基础。

这里有一个必须坦率讲清的事实：Interhuman Inter-2 已经在做犹豫、困惑、参与状态和带依据的社会信号分析。我们的切入与它相近。真正的研究价值，要通过中文自然交流、变化定位、时延和错误率的同条件实验来证明。不能仅靠换一个名字或多几个标签，宣布已经超过它。[Inter-2 官方研究说明](https://www.interhuman.ai/blog/how-we-trained-inter-2)

## 2. Perceive 与 Understand 的边界

你的划分是正确且适合工程实现的：**Perceive 认识“眼前这一刻”，Understand 把眼前这一刻与过去联系起来。** 这是我们为你们系统约定的边界，并非所有公司都采用同一套分法。

| 环节 | 回答的问题 | 例子 |
|---|---|---|
| Perceive | 当前表达和互动中出现了什么？ | “刚才两次停顿，并说‘我不太确定’，出现不确定表达。” |
| Understand | 结合这个人的历史，这次表现可能意味着什么？ | “他平时就会慢慢组织语言，这次变化主要出现在第二个话题。” |
| Predict | 接下来可能发生什么？ | “如果继续追问这个话题，可能进一步退出讨论。” |
| Engage | 系统现在如何回应？ | “先确认第二点，再提供一个更清楚的解释。” |

Perceive 可以读懂当前一句话，也可以使用刚刚的问题、当前指代对象和短期上下文。否则它无法区分“我现在很生气”与“电影里的人很生气”，也无法知道“第二点”指什么。

**允许短期上下文，不允许个人历史记忆。**

- 保留最近约 60 秒的音视频、转写和当前话题作为分析窗口；具体长度可在实验中调整。
- 可以比较“这几秒比刚才更频繁停顿”。
- 不查询姓名、历史对话、偏好、MBTI、长期声音特征或过去的面部基线。
- 不说“这个人一直很焦虑”“他平时就是这样”。
- 使用本次会话的临时人员编号，不做跨会话身份匹配。
- 会话结束后，推理缓存、临时人员编号和模型上下文一起重置。

科研录制可以单独保留用于标注和评测，但下一次实时推理不能偷偷读回这些材料。**保存研究样本与调用个人记忆是两件事。**

输入边界也要落实到 API：只接受当前音视频、当前文字、当前互动的必要上下文和临时编号；不设置“用户画像”“历史摘要”“个性化基线”这些输入字段。云模型本身的会话缓存也要纳入重置规则，不能只清空前端。

## 3. 第一版具体识别什么

### 3.1 五类输出，三类作为重点验收

| 类别 | 第一版输出 | 做到什么程度 | 不把它等同于什么 |
|---|---|---|---|
| **表达进程，重点** | 正在说话、暂时停顿、可能还在组织语言、结束候选 | 能区分停顿与结束；允许结果被后续语音修正 | 不能把安静一秒直接视为发言结束 |
| **犹豫与不确定表达，重点** | 停顿、重复、改口、不确定用语及它们的组合 | 识别出现时间、对应话题和持续变化 | 不推断长期缺乏自信或性格 |
| **澄清与困惑线索，重点** | 明确说没听清、没明白、追问、要求解释；其他线索仅作候选 | 明确表达可靠输出；非明确情况展示依据与不确定性 | 不声称知道对方脑内是否真正理解 |
| 当前立场表达，基础 | 同意、否定、保留意见、混合表达 | 以当前话语为主，点头等动作作为补充 | 不推断长期价值观或真实内心立场 |
| 参与行为与朝向变化，基础 | 转头、离开画面、停止回应、注意方向变化等 | 描述行为；证据足够时才提出参与变化候选 | 看向摄像头不等于投入，低头不等于失去兴趣 |

五类可以同时存在。例如“仍在说话 + 对第二点不确定 + 请求澄清”。不要强迫一个人只处于一种情绪或一种状态。

“语音与画面不一致”作为补充观察，不作为第六个必须做强的主产品。说“没事”同时叹气，可以报告两个可见可听的线索及其差异；不直接结论为隐藏情绪、撒谎或不信任。

### 3.2 保留哪些基础模块

| 模块 | 第一版必须具备 | 深度边界 |
|---|---|---|
| 当前内容 | 实时转写、当前语意、否定/引用/自我表达/指代区分 | 不做完整知识问答 |
| 声音 | 说话活动、停顿、重复、语速变化、音高/能量线索、少量非语言声音 | 情绪模型可提供辅助，不堆几百项给用户 |
| 面部 | 人脸有效性、头部方向、点头/摇头候选、眉眼嘴等动作与变化 | AU 与普通表情观察；不以“读心式微表情”为承诺 |
| 身体 | 上半身是否可见、明显转向、前后倾、手部活动变化 | 不建立完整肢体心理学分类器 |
| 时间 | 对齐、滚动窗口、变化检测、过期处理、结果修订 | 不做长期个人画像 |
| 结果与证据 | 状态、变化、时间段、原话/片段依据、未知原因 | 不混入回复、动作方案和个人判断 |

画面意义仍然保留：手里拿了什么、是否在看一份材料、是否被外部声音打断，都可能改变对当前交流的解释。但第一版只分析与当前交流有关的局部画面信息，不扩展为一个通用视觉智能平台。

### 3.3 为什么暂时不把“微表情”设成长板

普通摄像头上的面部动作、眉头变化和短暂表情可以研究。严格的微表情识别还涉及很短的发生过程、采样条件和单独的评测任务。MediaPipe 的 blendshape、OpenFace 的 AU 与微表情识别不是同一项能力。第一版可以做强面部动作证据，但不把它包装成已经理解隐秘心理。[MediaPipe Face Landmarker](https://ai.google.dev/edge/mediapipe/solutions/vision/face_landmarker)、[OpenFace 3.0](https://github.com/CMU-MultiComp-Lab/OpenFace-3.0)

## 4. 最终呈现成什么样

最终交付两件东西：**一个可独立使用的实时感知接口，加一个用于演示和科研检查的看板。**

看板只有四个主要区域：

1. 当前画面与正在更新的转写。
2. 当前交流状态，重点只突出一至三条有依据的信息。
3. 最近一分钟的变化时间线。
4. 点击某条结果，查看原话、对应声音/画面片段，以及系统不能确定的部分。

具体输出应该像这样：

> 当前：仍在表达，出现不确定表达。
> 变化：从 18 秒开始，停顿与改口增多。
> 主要依据：“不过……我不太确定第二点。”
> 声音依据：这句话内出现两次较长停顿。
> 画面依据：此时头部转向一侧；这一动作本身不能证明不确定。
> 待确认：画面线索较弱，主要判断来自话语与声音。

上面是理想输出示例，不是现有系统测量结果。

对外 API 输出三层：

- **观察**：原话、停顿、头部动作、画面有效性等。
- **当前信号**：哪些交流线索被支持，哪些还只是候选。
- **变化**：相对于本次短期窗口，何时开始、增强或消失。

每条结果附带本次会话编号、临时人员编号、媒体时间段、生成时间、证据引用、质量状态和版本号。必须区分媒体的发生时间与模型完成计算的时间。

结果允许经历“初步发现 → 更新 → 确认或撤回”。例如新语音证明刚才只是思考停顿，就撤回“结束候选”。看板不把初步结果画成永久事实。

显示“依据充分/一般/不足”即可。算法分数尚未通过实测校准时，不展示“83% 的真实概率”。每类信号单独判断可靠性，不能把四种模态的分数平均一下当成统一准确率。

## 5. Demo 做到哪里就停止

### 5.1 必须完成的范围

- 实时摄像头和麦克风输入，中文优先，分析一个被观察的人。
- 上面五类状态有稳定的输出格式，重点做好前三类。
- 人在说话时就能更新，不能只在整段结束后出一份总结。
- 同一个信号能显示开始、变化和结束，并提供可回看的证据。
- 声音听不清、脸被遮挡、多人出现、模型超时，都有明确的质量或未知状态。
- 会话清空后，不继续携带上一人的状态或云模型上下文。
- 能导出当前研究记录；另一个简单程序能订阅感知结果。
- 至少一轮包含未参与调试的人的现场或录制评测。

### 5.2 建议停止门槛

这些是研究 Demo 的初始验收建议，需要先用小样本试验确认标注规则可行，再固定门槛进行留出评测。

| 项目 | 建议验收方式 |
|---|---|
| 连续运行 | 至少连续 10 分钟现场输入，状态继续更新，无持续排队积压和状态串人 |
| 速度 | 基础动作/说话活动目标约 0.2–0.5 秒内更新；语意社会信号目标在所需证据出现后约 1–2 秒内给初步结果；记录 P50/P95 与失败率 |
| 核心信号 | 明确可标注的犹豫/不确定表达、明确澄清请求，初步目标精确率 ≥80%，同时报告召回率，避免靠少报来做漂亮数字 |
| 轮次 | 与现有固定静音阈值比较：过早结束明显减少，额外等待没有明显变坏；报告两项原始数字 |
| 证据 | 抽查每条结果的时间引用和原话引用；不存在大量引用错片段、虚构话语、无声音却声称听到叹气等问题 |
| 未知处理 | 关闭摄像头、静音、遮挡、多人出现时，对应模态和组合结论会降级，不能继续使用过期依据 |
| 非背稿 | 换人、换措辞、正常停顿和无特殊情绪的片段也能工作 |

1–2 秒的目标要从“足够证据已出现”开始算。系统无法在一句“不确定”尚未说出时，就可靠判断其具体对象；快更新也不意味着每 100 毫秒重新调用一次大模型。

**满足这些条件，就停止为第一版添加范围，进入实验和迭代。** 不再因为某个模型能生成更多标签，就增加一屏新功能。

### 5.3 第一版不要求完成

多人关系与团队气氛、跨会话识人、长期人格画像、历史记忆检索、未来行为预测、自动对话、机器人运动控制、生理传感器融合、微表情专题模型、完整世界模型，以及所有模型全部部署在机器人本体。

这些方向可以保留在路线图中。它们不作为第一版成功的必要条件。

## 6. 实时系统怎么搭

**确定采用：轻量连续测量 + 强音视频模型分析 + 自己的时间与证据整理层。** 模型可以在本地、独立 GPU 服务器或 API；前端和感知接口不随模型变化。

整体数据流：

    麦克风、摄像头、当前互动文本
                ↓
    同一时间轴 + 本次会话短期缓存
                ↓
    连续基础测量 ─── 强音视频语意分析
                ↓
    合并证据、定位变化、处理未知与修订
                ↓
    实时感知事件 → 看板 / Understand / 机器人软件

### 6.1 连续基础测量

- VAD 持续测说话活动；声音窗口测停顿、能量、音高等。
- 实时 ASR 提供变化中的文字；文字可修订。
- 面部与身体按适当帧率连续测动作。
- 停顿出现时运行轮次模型，提出“可能说完”或“可能继续”。

这条链不能等大模型返回后才继续工作。小模型与测量工具的用途是持续和稳定，不是因为预算不足而退而求其次。

### 6.2 强音视频模型

首轮工程主线用 **Qwen3.8-Omni-Flash-Realtime API** 接入强音视频能力，与你们已有千问桥接代码衔接。**MiniCPM-o 4.5** 同时作为第一优先级的开源全双工实验；**Qwen3-Omni-30B-A3B** 作为开源全模态对照；**Gemini Live** 作为通用 API 对照。最后由同一任务的结果决定替换或保留，不能仅看厂商的一般榜单。

音视频模型接收对齐的原始声音与画面，而不只接收转写。否则语音韵律和音画之间的信息会丢掉。当前问题或最近对方一句话可以作为辅助文本输入。

对于不便持续主动输出结构化信号的接口，可以用短音视频窗口进行滚动分析，例如覆盖最近约 2–6 秒、每约 1 秒或关键事件触发一次。这是可实施的初始实验方案，参数随速度和准确率一起调整。必须标明它是滚动窗口分析，而不是未经验证的逐帧社会理解。

MiniCPM-o 的全双工能力为另一条路径提供基础，但“能够边看边听边说”不自动等于“能稳定边看边输出我们的五类结构化信号”。它要通过输出格式、时序依据和不确定性测试才成为主引擎。[MiniCPM 官方仓库](https://github.com/OpenBMB/MiniCPM-V)、[Qwen Omni 实时接口](https://help.aliyun.com/zh/model-studio/realtime)

### 6.3 自己必须做的部分

模型接口之上必须实现：统一时间戳、短期缓存、临时人员绑定、信号定义、证据引用、变化检测、迟到结果处理、过期处理与撤回。

不同模型可以并行用于研究对照，但正式演示每类能力选一条主路径。不要把三个相近模型的自由文字结果直接拼在一起。需要研究集成时，按已定义的信号和证据比较它们，明确哪条依据可信、哪条有冲突。

原始采集时间尽量在设备端记录。跨设备输入需要处理时钟差异；网络接收时间不能代替采集时间。音频用采样位置映射到媒体时间，视频帧携带采集时间；重采样、裁剪和传输后的偏移都要保留。

队列忙时保留最新窗口，取消或跳过过期任务。晚到十秒的结果可以用于回看，不覆盖“当前状态”。看板要显示结果年龄，而不只是连接成功的绿灯。

## 7. 市面产品：长处、借鉴与对我们任务的缺口

以下是公开说明能支持的能力比较。“缺口”主要指与我们目标的适配问题，不等于已证实产品效果不好。各家的准确率与速度宣传，使用不同数据和条件，不能直接排列高低。

| 产品 | 主要能力与长处 | 我们借鉴什么 | 对我们这版的适配问题 / 需要验证什么 |
|---|---|---|---|
| **Interhuman Inter-2** | 音视频社会信号，官方研究列出 10 个评分信号，另有参与状态与每个信号的置信等级；重点是时间与证据落地 | 少而明确的社会信号、同段音画对齐、人工标注一致性、声音错配实验 | 它是最接近的竞争/对照对象。中文自然交流、实时事件边界、我们需要的轮次状态与部署方式应实测，不凭公开页面判断谁更强 |
| **Hume Expression Measurement** | 当前产品页面强调声音；实时 Prosody 与离线 Tagger，覆盖情绪表达、声音品质与说话方式 | 将音色、语速、犹豫等声音线索与内容一起看；提供流式测量 | 很多维度不等于更易用；必须缩成我们五类信号。其当前页面和旧多模态接口说明需区分，不混成一个产品承诺 |
| **audEERING devAIce** | 声音 SDK，包含语音活动、表达分析和其他音频模块；表达有唤醒度/正负倾向/主导性及四类标签 | 客观声音测量、音频质量、可独立使用的模块 | 音频能力不能单独补齐视觉证据、当前语意和信号时间线；适合声音对照 |
| **MorphCast** | 浏览器端面部分析，易嵌入；当前 FAQ 说明同时分析一个主要人脸 | 浏览器演示、模块事件、设备内面部处理 | 面部线索不能单独代表整个交流；朝向与注意/投入之间的关系仍需验证 |
| **Noldus FaceReader** | 科研面部行为分析，提供 20 个 AU 与相应检查工具 | 面部动作编码、逐段回看、研究标注方法 | 专业面部分析工具不直接等于语意、韵律与交流信号融合接口 |
| **Smart Eye / Affectiva** | 面部行为与媒体研究产品，长期围绕实际研究流程形成工具 | 质量控制、不同采集条件下的验证、按时间查看反应 | 对媒体反应分析的长处，不能直接外推为实时单人对话变化识别能力 |
| **Gemini Live** | 原始音频、图像与文字实时交互，WebSocket；官方当前说明视频图像输入不高于 1 帧/秒 | 强通用音视频能力、转写、连续输入和互动机制 | 通用对话功能不提供经过我们任务验证的社会信号定义；细微快速面部动作仍应单独测 |
| **Qwen Omni Realtime** | 当前文档优先推荐 Qwen3.8，支持音视频双工、语义 VAD、流式输入和多种连接方式 | 与现有看板衔接、中文原始音视频理解、升级轮次机制 | 需要新的结构化输出与主动分析调度；升级模型名不能自动把旧“句后决策”变成持续感知 |

来源分别为：[Inter-2 研究](https://www.interhuman.ai/blog/how-we-trained-inter-2)、[Hume 当前产品页](https://www.hume.ai/expression-measurement-api)、[devAIce](https://www.audeering.com/products/devaice/)、[MorphCast FAQ](https://www.morphcast.com/learn/emotion-ai-html5-sdk-faq/)、[FaceReader FACS](https://noldus.com/facereader/facs)、[Smart Eye](https://smarteye.se/solutions/behavioral-research/media-marketing/)、[Gemini Live 规格](https://ai.google.dev/gemini-api/docs/live-api)、[Qwen 实时文档](https://help.aliyun.com/zh/model-studio/realtime)。

### 对 Interhuman 最值得学习的东西

它的重点已经超过简单分类表情。其公开研究强调社会信号需要定位到时间段、识别支撑证据，并在实时预算内输出；还强调音画落地的训练与验证。学习这些方法比照抄它的标签列表更重要。[Inter-2 研究说明](https://www.interhuman.ai/blog/how-we-trained-inter-2)

不把“我们有证据、他们没有”“我们承认不确定、他们读心”当作差异。Interhuman 自己也明确区分可观察线索与知道一个人真实思想/感受的能力。[Interhuman 框架说明](https://www.interhuman.ai/ethical-framework)

建议争取的实际优势是：**在中文当前交流中，以更少的误报、更准确的变化时间、更及时的输出，抓住表达受阻和澄清的关键片段。** 这是可测试的研究目标，尚未证明。

## 8. 开源与开放模型：优先级与怎么接

这里的“顶尖候选”按具体任务选，不宣称一个模型在所有维度世界第一。首先跑具有直接任务关联的强模型，再用同一数据和时延要求比较。

### 8.1 必须进入首轮实验的名单

| 项目 | 能力 | 我建议的角色 | 怎么整合 / 注意事项 |
|---|---|---|---|
| **[MiniCPM-o 4.5](https://github.com/OpenBMB/MiniCPM-V)** | 9B 全模态，持续音视频输入与全双工输出 | 第一优先级开源实时语意引擎候选 | 独立推理服务接对齐流；改成我们的信号任务。先测结构化输出与时序依据，不能只演示自然对话 |
| **[Qwen3-Omni](https://github.com/QwenLM/Qwen3-Omni)** | 原生声音、图像、视频与文字理解；30B-A3B 开放模型 | 强开源全模态基线、离线窗口分析与候选标注 | 服务器运行，可只输出文字。它与 Qwen3.8 云 API 是不同发布物，不能假设权重能力相同 |

| **[Smart Turn v3.2](https://github.com/pipecat-ai/smart-turn)** | 直接根据音频判断发言是否结束，支持中文 | 停顿/结束状态的基础模块 | VAD 检出停顿后，分析当前轮次音频。只解决轮次问题，不能被当成困惑或参与分析模型 |
| **[Silero VAD](https://github.com/snakers4/silero-vad)** | 连续语音活动检测 | 持续测量模块，现有代码已用 | 复用既有封装；有声/无声与说完/没说完要分别表示 |

OpenFace 3.0 的非商业研究许可，在本次科研方案中不作为排除理由。显存和算力也不作为排除理由。某模块暂不进主运行链，原因应是没有补充价值、延迟难满足、输出不稳定或功能越过当前范围。

### 8.2 值得做研究对照，但不全部塞进主链

| **[pyannote.audio](https://github.com/pyannote/pyannote-audio)** | 区分谁在何时说话、重叠语音等 | 留作多人扩展与离线分析；第一版先保证单个被观察人的声音不被错误绑定 |

专项情绪模型输出可以作为线索，不能覆盖当前内容的解释。一个表情模型输出 sad，并不自动证明这个人当前悲伤，更不解释原因。

### 8.3 确定的选型起点

**首版运行主线：已有采集与 WebSocket + Silero + Qwen3-ASR 1.7B 候选 + MediaPipe + Qwen3.8 Omni API + 自己的信号整理层。** Smart Turn 负责停顿时的结束候选检测。

**首批增强实验：MiniCPM-o 4.5 替换通用音视频引擎；OpenFace 3.0 替换或补充面部动作测量；MOSS-Audio 8B 补充声音证据。**

**科研对照：Qwen3-Omni、AffectGPT、R1-Omni、Nano-EmoX，以及可获得的 Inter-2/Gemini/Hume 接口。**

选型起点明确，最终主模型可随实验更换。能力要求和输出格式不变。模型输出不达标时，不通过把验收范围扩大或改名来回避问题。

这套安排没有按小设备做妥协。专门的动作测量与 ASR 模块存在，是为了拿到连续、可定位的证据；强模型承担声音、画面、语意之间的综合解释。

## 9. Anima：什么保留、什么改造、什么移出

源码版本：9a9ee12989c303fcc2e3587446cb2c8bb5b7ee26。以下路径均相对于 Anima 仓库根目录。

| 模块 / 文件 | 结论 | 具体处理与理由 |
|---|---|---|
| v5/social_v5/human_state.py | **保留结构，改字段** | source、observed_at、未知值和各模态分开有价值；改成观察/信号/变化，删掉本产品对长期基线的依赖 |
| scheduler.py | **保留并增强** | 独立任务和忙时拒绝避免积压；增加窗口版本、取消和迟到结果不覆盖当前状态 |
| speech_activity.py | **保留** | Silero 语音活动入口可直接复用，补齐媒体时间与新输出协议 |
| audio_features.py | **保留基础测量** | 音高、能量、停顿等有价值；已有 speech_rate 是代理测量，应结合 ASR 分词/字数，不能当成准确语速 |
| voice.py | **部分保留，主 ASR 改造** | 复用解码、质量处理和 SenseVoice/Whisper 对照。当前整段 WAV 转写不能当成已完成流式 ASR；TTS 移出 |
| face_geometry.py | **保留算法与实现经验** | 关键点、blendshape、方向有用。当前 iris 几何明确未校准，不能直接输出“看着机器人”；与浏览器实现选一条主路径 |
| expression_actions.py | **保留，作为动作候选** | 面部动作描述与稳定处理有用；用新数据验证阈值，不改称 AU 或微表情 |
| body.py | **薄层保留** | 保留可见性、转向、倾斜、活动变化；不补齐所有身体心理标签 |
| vision.py | **拆开** | 保留检测、图像解码、质量与表情基线；SFace 身份匹配从 Perceive 移出 |
| social_runtime.py | **较大改造** | 保留模态协调、会话引用、清理；去掉 MemoryStore、真实 uid 与画像授权耦合，改成临时 track/session |
| temporal.py 的缓存、过期、平滑 | **提取后保留** | 有短期稳定性与时间处理经验；不能原样搬，因为现在会读写个人基线 |
| temporal.py 的 user_model / baseline 持久化 | **移到 Understand** | 与“不知道个人过去”直接冲突；当前实现会在有授权时载入和保存历史基线 |
| temporal.py 的一致性和总置信度公式 | **替换** | 当前把声音标签粗略映射到正负值，与面部/文字比较；总置信度平均四模态分数。它们是工程启发式，不是验证后的综合判断 |
| temporal.py 的 response_plan / record_action | **移出核心** | 回复速度、语气、机器人姿态属于 Engage；动作后反应可留作独立实验，不进入当前人的长期画像 |
| memory.py、BGE 检索、长期事实/偏好 | **保留在系统其他部分** | Understand 将来可用；Perceive 的依赖树里不出现 MemoryStore |
| personality.py、MBTI | **移出** | 个人设置和画像不属于当前感知 |
| engine.py、conversation.py、care.py / care_api.py | **不作为 Perceive 主流程** | 现有对话、照护与记忆编排越过范围；保留给后续完整机器人系统 |
| predictor.py 与 V2/V4 文本预测头 | **保留研究基线，不作产品核心** | 旧任务与新五类信号不同，既有成绩不能代替本任务验证；不重训全套旧情绪/预测头作为前置要求 |
| robot.py、robot_bridge.py | **保留接入经验，移出动作执行** | 感知服务只发状态；动作控制留给 Engage |
| v5/web 的相机/语音生命周期与已有测试 | **选择性复用** | 保留资源清理、引用归属、过期和错误处理经验；登录、人物档案、照护、TTS UI 不进新 Demo |

关键代码依据：[HumanStateBuffer 的历史加载与存储](https://github.com/miracle121388-a11y/Anima/blob/9a9ee12989c303fcc2e3587446cb2c8bb5b7ee26/v5/social_v5/temporal.py)、[SocialRuntime 的记忆与身份耦合](https://github.com/miracle121388-a11y/Anima/blob/9a9ee12989c303fcc2e3587446cb2c8bb5b7ee26/v5/social_v5/social_runtime.py)、[状态结构](https://github.com/miracle121388-a11y/Anima/blob/9a9ee12989c303fcc2e3587446cb2c8bb5b7ee26/v5/social_v5/human_state.py)。

这里的“移出”不是删掉员工的工作。它们仍有用途，只是不加载进当前 Perceive 产品。原仓库应保留，提取出一个独立感知服务来使用。

选浏览器 MediaPipe 为首版主面部路径，是为了直接复用已有看板。OpenFace GPU 路径完成对照后，可替换或补充；同类数据只保留一条明确主来源，避免重复检测产生相互矛盾的结果。

## 11. 与实体机器人怎么连接

机器人在第一版中只承担两个角色：提供当前摄像头/麦克风流，以及订阅 Perceive 的状态事件。

先在 PC 或浏览器验证相同的输入输出协议，再让机器人接入。感知模型完全可以跑在远端服务器，机器人本体不必装全套大模型。

机器人需要做的是提供真实采集时间、输入中断状态和必要的相机位置说明。机器人说话时，应提供它正在播放的声音或文字用于排除自己的声音；否则可能把机器人 TTS 当成人的表达来分析。麦克风回声处理与输入绑定属于感知基础。

“看到人犹豫，所以机器人放慢语速”可以作为未来的联动展示，但放慢语速的规则和执行要放在 Engage。Perceive 只发“当前出现犹豫表达”及证据，不直接控制电机或生成回复。

实体机器人动作不是这版 Demo 的停止条件。能实时输入并让一个订阅程序拿到结果，就已证明感知模块可以被机器人系统使用。

## 12. 怎么证明有科研价值、怎样与现有产品比较

### 12.1 先有自己的小而清楚的测试集

建议起步使用 15–20 个不同人的约 100–200 段短交流片段，并加入若干连续交流录制。人数与样本量只是试验起点，不足以证明普遍适用。

至少两名标注者独立标注：原话、停顿、改口、明确澄清、否定/保留表达、行为变化与发生时间。模糊片段允许“无法确认”并保留分歧。不要把模型生成的情绪描述直接作为真值。

调试样本和验收样本按人分开，避免同一个人的不同片段同时落入两边。除演示短句之外，要有普通表达、思考停顿、引用他人情绪、否定、自嘲、语言与表情混合等正常复杂情况。

### 12.2 对照组与消融

| 对照 | 要回答的问题 |
|---|---|
| 同一强模型只看转写 | 音画究竟补充了什么？ |
| 同一模型只听声音 | 画面有无增加正确判断，还是制造误报？ |
| 同一模型只看画面 | 是否错误用表情代替语意？ |
| 完整音画与当前文本 | 综合结果是否有可重复的增益？ |
| 静音、交换声音、音画错位 | 模型是否确实使用对应证据？ |
| 现有固定静音结束规则 | 新轮次方法是否减少过早结束而不过度等待？ |
| Inter-2 / Hume / Gemini / Qwen 等可获得接口 | 在相同片段、相同输出定义和时延条件下，优势在哪里？ |

Inter-2 的信号定义与我们的输出不完全相同，比较时需要公布映射规则；不支持的轮次能力单独列为功能差别，不能算它识别错误。没有取得某产品接口并实测，就只写公开功能比较，不声称已击败。

### 12.3 必须报告的结果

每类信号的精确率、召回率、误报；变化定位误差；足够证据出现到初步结果的延迟；P50/P95；过早结束比例与等待时间；未知/撤回比例；证据引用正确率；正常持续运行中的失败率。

没有依据的“综合社会智能分”不作为主要结果。关闭一个模态后是否合理降级，也是重要结果。为了避免“全都不确定”获得很低误报，还要报告有效覆盖率和未知率。

公开基准可用来补充：**[MERBench / MERTools](https://github.com/zeroQiaoba/MERTools)** 研究不同模态、噪声与融合；**[OV-MER / AffectGPT](https://github.com/zeroQiaoba/AffectGPT)** 研究情绪描述与开放词汇；**[EmoBench-M](https://github.com/Emo-gml/EmoBench-M)** 检查多模态情绪理解。它们不能替代我们对实时交流变化的专门测试。

### 12.4 自己的研究贡献是什么

值得形成成果的贡献是：

1. 中文当前交流信号的清晰定义与带时间标注的样本。
2. 连续音画证据与语意之间的对应方法。
3. 犹豫/澄清等变化出现、增强和消失的定位。
4. 实时结果可以更新和撤回，而不是累积未经核验的标签。
5. 用缺模态、错配和留出人的测试证明增益与可靠性。

调用强模型能迅速得到基线。要形成自己的能力，需要把以上任务定义、整理层、数据与实验逐步建立起来。

## 13. 开发顺序与每一步的结束条件

| 步骤 | 做什么 | 结束条件 |
|---|---|---|
| 1. 收敛产品 | 固定五类输出、短期上下文边界、验收与标注规则 | 团队能对同一片段给出相近且可解释的标注 |
| 2. 提取现有基础 | 看板输入、协议与 Anima 感知模块；去掉个人记忆和决策依赖 | 匿名会话的音画流、时间和质量状态能正常贯通 |
| 3. 建强基线 | Qwen3.8 API；ASR、VAD、动作测量；产生带依据的滚动结果 | 人还在表达时就出现初步结果，证据能定位 |
| 4. 跑强开源对照 | MiniCPM-o、OpenFace、MOSS-Audio；必要时 Qwen3-Omni/专项情绪模型 | 找到具体增益，确定主链与研究对照链 |
| 5. 做变化与修订 | 时序、未知、结果撤回、迟到处理、时间线回看 | 停顿继续、信号消失、遮挡和断线都能正确处理 |
| 6. 留出验证并冻结 Demo | 换人、正反片段、消融、实时性能与接口订阅 | 达到约定的停止门槛，交付结果和失败例子 |

前三步可以先形成有用原型。模型训练、科研专题扩展与实体机器人复杂联动不设为前三步的前置条件。具体工期取决于人员和推理环境，在尚未测延迟与标注一致性之前不承诺固定几周全部做完。

## 14. 最终可以给团队的一段定义

> 我们要做一个实时多模态交流状态感知引擎。它只使用当前互动的声音、画面、文字和短期上下文，持续识别表达进程、犹豫与不确定表达、澄清线索、当前立场和参与行为变化，并给出时间位置与可核对的依据。第一版突出犹豫、澄清和表达受阻的变化定位。它不读取个人历史画像，不决定系统怎么回应。最终交付一个可独立接入的感知接口和一个能现场演示、回看证据的科研看板。

第一版到“实时、可定位、可修订、换人能用、有留出测试和开放接口”就停止扩范围。后续再用实测增益决定哪些面部、声音或社会信号值得继续加深。
