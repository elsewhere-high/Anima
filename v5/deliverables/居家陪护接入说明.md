# V5.2 居家陪护接入说明

本次是软件能力升级，保留 Qwen3.5-2B 和既有适配器，没有训练新权重。当前适合成年人、有人可接手的非医疗居家陪伴试用。没有连接实体机器人，不能据此宣称可无人值守照护、自动救援或医疗级跌倒检测。

## 当前补齐的关键环节

| 场景 | 当前行为 | 仍需注意 |
|---|---|---|
| 明确说“喘不过气”“摔倒起不来”“救命” | 本地规则快速回应，不等待普通大模型轮次，建议立即找身边人和当地急救服务 | 文本匹配不是经验证的急救分类器，存在漏报、误报；不自动拨号 |
| 自伤表达 | 优先关注当下安全、现实中的陪伴和急救渠道 | 不宣称已经通知家人，不作为危机监测设备 |
| 药量、停药、漏服问题 | 部分明确请求直接转向医生/药师/说明书，不生成剂量调整 | 匹配规则并非完整医疗意图识别；模型仍需实际场景评估 |
| “五分钟后提醒我浇花” | 确认身份与记忆许可后写入加密提醒，保存成功才返回回执 | 不支持的自然时间会要求澄清；具体日期/重复规则用表单 |
| 提醒到期 | 已登录页面每 5 秒检查；显示、知晓、延后 10 分钟、取消有不同状态 | 页面/机器人接收端和服务须保持运行；不自动确认完成 |
| 设备重启错过提醒 | 未确认提醒仍在数据库里，恢复后显示已到期，不伪装准时送达 | 每日重复按 24 小时计算，不支持夏令时的“固定本地钟点” |
| 主动关怀 | 默认关闭；明确开启后，按间隔、安静时段、是否有人及是否忙碌决定 | 网页只显示，不自动朗读；没有可靠在场证据就不主动发起 |
| “不要打扰我” | 抑制主动关怀；登录且同意记忆时保留安静选择，明确恢复后再继续 | 紧急求助仍可得到安全回应 |
| 独居孤单、重复提问、情绪变化 | 提示模型先倾听、少追问、避免重复空话、不擅自诊断，支持现实亲友关系 | 提示词优化不等于已证明长期陪伴质量提升 |
| 多人同框 | 保留原有身份边界；私人提醒不自动向房间朗读 | 人脸候选不能替代登录，也不能证明当前说话者身份 |
| 伪造设备授权 | 公共对话接口强制剥离 JSON 中运动、任务、急救认证与云端授权标志 | 实体控制仍必须经过厂商控制器 |
| 机器人掉线或急停 | 独立心跳、6 秒过期、低电量限制、输出有效期；一直返回 HOLD，不发电机命令 | 软件心跳不能代替硬件急停、避障和碰撞检测 |

## 页面使用

启动现有 `start_v5.ps1`，打开 `http://127.0.0.1:8768/`。完成四步准备后，在“设置 → 提醒与主动关怀”中设置。记忆许可关闭时不能创建持久提醒。

提醒只在本机接收界面显示，不自动发消息给家人。“我知道了”仅表示用户确认看到了提醒，特别是用药提醒，不代表系统验证了服药或任务完成。撤回记忆许可、清空记忆、删除成员都会删除相应提醒和陪护偏好。

主动关怀间隔支持 30–240 分钟；默认安静时段为 22:00–08:00，网页保存当前设备的 UTC 偏移。安静起止相同表示不设置固定夜间窗口；用户主动要求安静仍优先。网页仅在近期检测到单人画面时报告在场，缺失或多人时不主动问候。

## 对接机器人大脑

现有机器可以直接作为本地大脑服务运行。厂商程序输入语音识别文本、硬件状态，读取结构化回复；本次提供可运行的标准库 JSON-lines 桥接程序 `v5/robot_bridge.py`，不是某个未知型号的电机驱动。

先为大脑服务和桥接进程注入相同的 `SOCIAL_ROBOT_TOKEN`（至少 24 个字符，不要使用示例固定密钥）。默认仅监听回环地址；跨机器使用 HTTPS 和原有 `SOCIAL_API_TOKEN` 网关鉴权。

```powershell
# 在启动大脑服务之前设置，桥接进程也使用同一个环境变量。
$env:SOCIAL_ROBOT_TOKEN = (& .\.venv_zh\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(32))")
.\stop_v5.ps1
.\v5\start_background.ps1
# 等待 /health 返回 ready 后：
.\.venv_zh\Scripts\python.exe .\v5\robot_bridge.py --check
.\.venv_zh\Scripts\python.exe .\v5\robot_bridge.py --robot-id living-room
```

上述命令只配置软件连接，不会调用真实扬声器、麦克风或电机。桥接程序通过 stdin 接收 JSON 行，通过 stdout 输出 JSON；厂商 SDK 应以子进程方式接入。

```json
{"type":"hardware","emergency_stop":false,"speaker_ready":true,"display_ready":true,"battery_percent":85}
{"type":"speech","text":"今天有点想家","asr_confidence":0.9}
{"type":"poll","person_present":true,"interaction_busy":false}
{"type":"help"}
```

硬件状态至少每 2 秒更新一次；默认急停为真，6 秒未更新便停止允许朗读。桥接读取硬件状态不等待普通聊天线程；`help` 可抢先走快速求助路径，旧轮次输出会被丢弃。队列有界，忙时拒绝新请求，不无限积压。接收端还必须检查输出 `created_unix` 和 `expires_after_ms`，不执行过期回复；本机时钟应正确，跨机需同步时钟。

屏幕和语音的实际呈现由厂商 SDK 完成。所有输出的运动命令都是 `HOLD`；没有导航、机械臂、扶人、自动开门、自动呼叫或药物控制功能。低电量、急停和掉线只限制本协议输出，不能作为真实机器人唯一安全措施。

成员私有功能需要桥接进程的 `COMPANION_MEMBER` 与 `COMPANION_PIN` 环境变量。凭据不在 JSON 输入或日志中输出；桥接会提前刷新登录会话。未经本人许可不要将家庭成员凭据预置给任何陌生人可操控的终端。无成员登录时可以聊天，但无法读取个人提醒。`poll` 的在场/忙碌字段必须由接入端真实填写，不应恒定伪造为在场且闲暇。

提醒确认输入示例（id 和 occurrence 必须来自刚收到的提醒，不可猜测）：

```json
{"type":"reminder","id":123,"occurrence":"123:1770000000.000000","action":"ack"}
```

`action` 可为 `ack`、`snooze`、`cancel`；`snooze` 可带 `minutes`。未经用户确认不要发送 ack。带旧 occurrence 的重复确认会被拒绝，防止把下一天的提醒误确认。

## HTTP 接口

所有 `/v1/care/*` 使用 `X-Member-Session`，并沿用已启用的网关令牌。所有 `/v1/robot/*` 另外要求 `X-Robot-Token`。

| 接口 | 内容 |
|---|---|
| `GET/PUT /v1/care/settings` | 主动关怀开关、间隔、安静时段和 UTC 偏移 |
| `GET/POST /v1/care/reminders` | 待办列表、创建提醒；创建须 request_id，delay_seconds 或带时区 due_at 二选一 |
| `POST /v1/care/reminders/{id}/resolve` | 带 occurrence 的确认、延后或取消 |
| `POST /v1/care/poll` | 到期提醒和可选主动关怀；读取不会确认提醒 |
| `GET /v1/robot/capabilities` | 接入能力与限制 |
| `POST /v1/robot/heartbeat` | 设备心跳与输出条件 |
| `GET /v1/robot/status/{robot_id}` | 心跳是否过期、是否要求保持停止 |
| `POST /v1/robot/turn?robot_id=...` | 对话结果与有时效的输出信封；必须先有心跳 |

## 还不能省略的接入条件

必须明确机器人型号、操作系统/CPU/GPU/RAM、厂商 SDK 或 ROS 接口、麦克风阵列和回声消除、离线中文 TTS、硬件急停和避障、陪护人群及可接手的人。目前尚未收到这些信息，因此没有部署到真实机器人，也没有开展家庭现场长时间验收。

当前 Windows DPAPI 加密的数据不可直接复制到 Linux/另一 Windows 账户解密；在新机器人上首次部署应创建新成员和密钥。已运行数据需要另行设计明确授权的解密导出与重新加密迁移，不能只复制 SQLite 文件。

紧急提示的基础参考为 [国家卫健委关于 120 的说明](https://www.nhc.gov.cn/xcs/c100122/201411/32c1bd8c5b13436ba9ec83ef1834856e.shtml)、[NHS 呼吸困难求助说明](https://www.nhs.uk/symptoms/shortness-of-breath/) 和 [NHS 跌倒后求助说明](https://www.nhs.uk/conditions/falls/)。这些来源不证明本软件的识别准确率，也不构成医疗器械认证。

测试证据：`v5/reports/care_upgrade_tests.xml`、`v5/reports/care_live.json`。测试数据与真实家庭成员数据分离；软件回归通过不代表无人值守家庭照护验收通过。
