# V5.1 部署与接口（2026-10-01）

## 本机运行

```powershell
./start_v5.ps1 -Profile balanced
# 更低资源：
./start_v5.ps1 -Profile ultra_light
# 额外面部几何：
./start_v5.ps1 -Profile best_edge
# 明确选择设备：
./start_v5.ps1 -Profile ultra_light -Device cpu
```

网页 http://127.0.0.1:8768/；接口文档 `/docs`；`/health` 返回实际档位和后端。CPU Qwen 继续使用 V4 原有实验性混合量化文件，其历史精度偏差不会因这次升级自动消失；本次整机对比在 CUDA 上完成。没有 ARM/RKNN/TensorRT/NPU 实机验收，不宣称当前 Windows 包可以直接运行于未知机器人芯片。

`auto` 对物理内存至少 12GiB 且至少 8 个逻辑 CPU 的机器选择 balanced，否则 ultra_light；感知仅用 CPU，GPU 留给唯一 Qwen。已有私有数据库由追加表迁移，个人数据不搬入报告。原代码快照在 `reports/upgrade_20261001/before/`。

环境为项目 `.venv_zh`。新增正式依赖：MediaPipe、sherpa-onnx、ONNX（准备脚本）、soundfile（测试）、opencv-contrib-python 4.11.0.86；完整实际环境见 `requirements.lock.txt`。OpenCV 只装一种发行包，避免和 headless 版本重叠。

上述下载/准备是开发部署步骤，正式服务不会自动下载模型。发行包直接携带已校验的文件和 `models/social/manifest.json`；模型加载时校验 SHA256。不要把 `reports/upgrade_20261001/candidate_deps` 或 emotion2vec 研究 checkpoint 加入生产 PYTHONPATH。

SenseVoice 下载的是固定 revision 的 sherpa ONNX 转换，来自 FunAudioLLM 的 SenseVoiceSmall；保留模型名、来源和 FunASR 模型许可。Py-FEAT/LibreFace 的研究或非商业限制使其没有进入正式 runtime。EmotiEffLib 的代码许可和其训练数据来源是不同问题，不能把 Apache 代码许可解释成所有训练数据商业权利的证明。详细来源在 `THIRD_PARTY_NOTICES.md`。

## 数据与调用链

摄像头 → YuNet/SFace/B0、轻量姿态（高配可加面部几何） → HumanStateBuffer。
麦克风 → 本地分段 → 唯一 ASR/SER 后端、DSP → 同一 HumanStateBuffer。
用户轮次/声音事件 → 压缩 HumanState + 既有历史/记忆/明确偏好 → 同一个 Qwen → response_plan → 朗读及受控行为建议 → 后续观测关联。

视觉、身体、音频分开工作线程；每条通道最多一个运行作业，多余请求返回 429。浏览器连续感知会延后重试。模型是同步单次推理，但不同通道可以并行；这不是音频全双工，也不是 GPU 并行加载多套大模型。

同一个交互应使用相同的 `camera_id` 和 `session_id`。成员请求继续携带 `X-Member-Session`，访客依靠 HttpOnly 会话 cookie 隔离。客户端不能直接上传 HumanState、基线或身份验证结果；只能提交原始短帧/短音频，或引用服务端生成的短时令牌。

| 接口 | 新增行为 |
|---|---|
| POST `/v1/vision/analyze` | 原格式不变，增加 human_state、sampling.next_sample_ms；质量不足/多人不绑定个人信号 |
| POST `/v1/voice/transcribe` | 接收 audio_base64、session_id；返回 text、voice、audio_frame_id、human_state |
| POST `/v1/step` | observation 可带 audio_frame_id；增加 human_state、response_plan，保留 response 和原设备控制字段 |
| GET `/v1/human-state?session_id=...` | 只读最新状态，不触发 Qwen、不增加基线样本 |
| GET `/v1/user-model` | 需 PIN 登录，读取本人获准持久化的统计与偏好证据 |

audio_frame_id 绑定 owner + session，有效 30 秒；visual_frame_id 沿用 10 秒限制。Face/Body 信号 5 秒过期，Voice/Language 15 秒过期，缺失字段是 null/空集合，不伪造 neutral。低置信度来源不参与连续数值融合。无文本的 Cry 标签会归一化为 Crying，可触发温和陪伴回应；安静/拒绝边界优先。

`response_plan` 包括状态解释、置信度、回应策略、实际文字、语速/音量建议、机器人行为建议和记忆更新说明。策略由有界融合控制器选择，Qwen 根据压缩状态生成自然回复，JSON 包装由程序构造；不是谎称小模型已经通过自由生成完整动作 JSON 的评测。网页将语速/音量建议用于朗读，warmth 为提示字段，实体动作没有接通、没有自动授权。

## 个体化与保留范围

时间模块使用时间感知 EMA（约 2 秒时间常数），保留最多 120 秒/300 个样本，提供约 10 秒和 30 秒斜率、current/baseline/delta。每至少 5 秒接纳一组独立基线观测，质量加权、慢更新、30 天衰减并限制离群影响；每项有效样本量达到 20 且累计观察覆盖 120 秒后才用于成熟基线比较。反复轮询不会制造训练样本。

摄像头个人基线持久化需要已登录、有长期记忆许可且人脸候选与成员一致；未登记/未确认的单人线索只用于当前会话，不以登录身份强行认定摄像头中的人。音频按已登录的当前交互归属，尚无多人声纹分离，因此多人混说不具备可靠个体归因。

交流偏好只从重复明确请求统计，至少三次才作为长期软提示，带置信度、衰减和冲突权重；当前明确要求及用户自选设置优先。Big Five、信任和隐含人格保持未知。robot_action → human_state_delta 只是时间相邻关联，不证明因果、不自动把一次负面变化写成“用户讨厌这种方式”。

用户模型正文采用已有 Fernet 加密及 Windows DPAPI 密钥保护。撤回记忆许可、清空所有记忆和删除成员会删除统计，清理短期缓存；退出登录清理该成员会话缓存。原视频/音频不长期保存。运行时缓冲最多 128 条感知会话，闲置 300 秒回收，独立模型结果短时缓存有数量上限。

## 复现验证

```powershell
.venv_zh/Scripts/python.exe -m pytest v5/tests -q
.venv_zh/Scripts/python.exe v5/scripts/run_upgrade_benchmarks.py
.venv_zh/Scripts/python.exe v5/scripts/verify_social_http.py
```

benchmark 在独立进程顺序运行，固定公开图像及同一段 5.592 秒中文音频，不调用麦克风、在线 TTS 或保存用户媒体。`audit_social_hardware.py` 是额外设备检查，会短暂读取本机摄像头并释放，不保存帧；它测量采集 FPS，不做人脸识别。

五类逻辑场景包含“没事但非语言偏负”“相对本人突然下降”“笑着抱怨”“无文本哭声”“回应后状态变化”。这些合成信号测试用于证明融合、时序和控制边界；真实编码器/HTTP/整机回放另有证据。它们都不是家庭场景识别准确率、长期人格有效性或医学诊断验证。
